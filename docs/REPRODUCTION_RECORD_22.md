## 2. 새 빈 폴더에서 같은 커밋 받기 (학생 PC에서 실행)

작업 위치: 원래 폴더 **밖**의 빈 폴더(예: 바탕화면의 새 폴더). 새 폴더 PowerShell 열기: 폴더 주소 표시줄에 `powershell`을 입력하고 Enter.

```powershell
git clone https://github.com/zaqxsw108091-create/choi-bujang-secret-vault.git reproduce-22
```

```powershell
cd reproduce-22
git checkout <제출할 40자리 커밋>
git rev-parse HEAD
```

- 정상: `git rev-parse HEAD` 값이 제출할 40자리와 같습니다.
- 이상: 값이 다르거나 `reference is not a tree` 오류 → 아직 GitHub에 올리지 않은 커밋입니다. 올린 뒤 다시 합니다.
- 주의: 받아지는 것은 **커밋된 파일뿐**입니다. 내 PC 원래 폴더의 저장하지 않은 변경(시작 틀 `0.2.21` 갱신)은 새 폴더에 없습니다. 인증·설정 파일은 복사하지 않습니다.

## 6. 데이터 보존 계획

- 앱(`on-client`)은 파일·브라우저 저장소에 학생 데이터를 쓰지 않습니다(`on-client/src`, `on-client/student`, `on-client/public/app.js`에서 파일 쓰기·`localStorage`·`sessionStorage` 사용을 검색했고 찾지 못함. 코드로만 읽음). 앱을 지워도 지워지는 학생 데이터는 없습니다.
- 학생 자료는 세 곳입니다: ① Git 기록(저장소 전체, GitHub에 올린 커밋), ② 학습용 Supabase의 가상 메모와 비공개 사본 표 `notes_backup`·`notes_restore_audit`(10단계, 자세한 내용은 `README.md` 10단계), ③ 학생 PC의 비밀 설정 파일.
- 백업: 문서와 코드는 GitHub에 올린 커밋이 백업입니다. 비밀 설정 파일·비밀번호·토큰·열쇠는 Git과 이 문서에 넣지 않으며 담당자가 안내한 프로젝트 밖 위치에 직접 보관합니다.
- 복원: 새 폴더에서 같은 커밋을 받으면 코드와 문서가 돌아옵니다(2장). 가상 메모는 10단계 `POST /api/restore`로 한 건씩 비공개 사본에서 되살립니다. 이 복원은 지난 단계에서 확인한 범위이며 이번 22단계에서 다시 실행하지 않았습니다(미확인).
- 한계: 비밀 설정 파일은 새 폴더에 따라오지 않으며 무작정 복사하지 않습니다. 사본은 처음 저장된 상태입니다(`README.md` 10단계). 저장하지 않은 변경(`0.2.21` 갱신)은 커밋하기 전까지 새 폴더에 없습니다.
