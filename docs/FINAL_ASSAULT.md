# 마지막 총공세: 내 PC 관제 · 케셰브 (완성본 정리)

22단계까지 만든 케셰브 앱(`on-client`)을 **내 PC에서 쓰는 앱**으로 완성한 기록입니다.
확인하지 않은 것을 된다고 쓰지 않았습니다. 확인한 것과 확인하지 못한 것을 나눠 적었습니다.

- 작업 브랜치: `final-assault` (22단계 제출 커밋 `1adac056ec00feae7a7cac9106eaf7a5fdedb0ef` 위에서 이어 만듦. 22단계 브랜치와 기록은 그대로 남아 있음)
- 포장(`npm run package-app`)은 하지 않았고, 새 포장 스크립트도 만들지 않았습니다.
- 외부 서버 연결 기능은 만들지 않았습니다. 기본 상태는 연결 없음입니다.

## 2. 핵심 기능 3가지

1. **내 PC 상태** (제공 기능 + 내가 더한 이전 조회와의 비교·설명)
2. **기록 보기** (조회 기록, 그래프, 목록, 기록 지우기)
3. **위험 알림** (기준을 넘으면 알림, 읽지 못한 항목은 따로 안내)

## 3. 실제로 잰 값과 예시 값의 구분

- 내가 만든 칸(「학생 구현」 표시)은 **제공 「내 PC 상태」가 이 PC에서 실제로 잰 값만** 씁니다. 예시 값을 만들어 채우지 않습니다.
- `npm run demo`로 켜면 제공 화면의 로그인·기기·접속 판정 등은 「예제 데이터(demo) · 실제 연결 아님」으로 표시됩니다. PC 값은 예제 모드에서도 실제로 잰 값입니다.
- 읽지 못한 값은 「확인 불가」와 이유(권한 없음·시간 초과·이 운영체제에서는 조회하지 않음 등)로 보여 주며, 정상이나 0으로 바꾸지 않습니다.
- 「확인 불가」는 값을 읽지 못했다는 표시이며, 방어전 판정 카드의 「확인 불가」와는 다른 뜻입니다.
- 조회에 실패하면 이전 값을 이번 값처럼 보이지 않게 비우고, 실패 이유와 다음에 할 일을 보여 줍니다.
- 위험 알림은 기준값(CPU 70% 이상, 메모리 80% 이상, 디스크 남은 공간 15% 이하, 방화벽 꺼짐, 네트워크 구성 0개)을 넘었다는 뜻입니다. **침해(공격) 판정이 아닙니다.** 방화벽이 켜져 있거나 경고·오류가 적어도 PC가 안전하다는 뜻이 아닙니다. 기준값은 학습용이며 공식 보안 기준이 아닙니다.
- Windows 경고·오류 건수와 네트워크 구성은 「참고」로만 보여 주고 정상으로 세지 않습니다.

## 4. 실행 안내 한 장 (처음 보는 사람용)

필요한 것: Node.js 22~24 (수업·검사 기준 24.19.0). 따로 설치할 패키지는 없습니다.

1. 이 저장소를 받고 `final-assault` 브랜치로 이동합니다. (`git switch final-assault`) ZIP으로 받았다면 압축을 푼 폴더에서 시작합니다.
2. 파일 탐색기에서 `on-client` 폴더를 열고, 위쪽 주소창에 `powershell`을 입력한 뒤 Enter를 누릅니다.
3. 아래 중 하나를 실행합니다.

```
npm run demo
```

```
npm start
```

Windows에서 제공 실행 도구를 쓰려면(안내: `on-client/docs/STUDENT_LAUNCH_GUIDE.md`):

```
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

4. 브라우저에서 `http://127.0.0.1:5189/` 를 엽니다. 포트가 다르면 터미널에 나온 주소를 엽니다.
5. 왼쪽 메뉴 **보호 현황** 화면의 **「학생 상태·알림 표시」** 칸 맨 위에 「내 PC 기록·추이·위험 알림 (학생 구현)」이 보입니다.
6. 끄려면 PowerShell 창에서 `Ctrl+C`를 누릅니다.

막혔을 때:

- `node`를 찾지 못하면 Node.js를 설치합니다(https://nodejs.org).
- Node 버전이 맞지 않으면 실행이 멈출 수 있습니다. 22~24 버전을 쓰세요.
- 화면이 열리지 않으면 터미널의 첫 오류 문구를 그대로 복사해 전달합니다.
- 이 PC에서 방화벽·경고·오류가 「확인 불가」로 나오는 것은 권한이나 운영체제 때문일 수 있습니다. 관리자 권한은 쓰지 않으며, 정상이라고 표시하지 않습니다.

## 5. 시연 순서

1. **내 PC 상태**: 보호 현황에서 제공 「내 PC 상태」의 「내 PC 확인」을 눌러 값을 읽고, 값마다 마지막 실측 시각이 나오는지 봅니다.
2. **기록 보기**: 「내 PC 기록·추이·위험 알림」의 「다시 조회」를 두세 번 누릅니다. 기록 목록과 그래프가 쌓이고, 「주의」·「확인 불가」로 거를 수 있고, 이전 조회와의 비교 문구가 나옵니다.
3. **위험 알림**: 기준을 넘는 항목이 있으면 「위험 알림」 상자와 알림 기록에 시작 시각이 나오고, 이후 조회에서 해소되면 해소 기록이 남습니다. 읽지 못한 항목은 「읽지 못한 항목」 상자에 이유와 함께 따로 나옵니다.
4. **한계 확인**: 확인 불가 항목이 정상으로 바뀌지 않는지, 기록 지우기에서 확인 창이 뜨는지 봅니다.
5. 키보드만으로도 「다시 조회」, 그래프 항목 선택, 기록 거르기, 기록 지우기를 쓸 수 있습니다(Tab, Enter, Space).

## 6. 아직 안 되거나 「확인 불가」로 남은 한계

- **Windows 확인은 PC 한 대, 한 번뿐입니다.** 개발에 쓴 환경은 Linux이고, Windows는 학생(윤대영)의 PC에서 한 번 켜 본 결과(아래 근거 표)만 있습니다. 그 PC에서는 모든 항목이 값으로 읽혔고 「확인 불가」나 「주의」가 나오는 상황은 보지 못했습니다. 다른 Windows 버전·다른 PC·권한이 부족한 PC(회사·학원 정책 등)에서는 확인하지 못했습니다. Linux 개발 환경에서는 방화벽과 Windows 경고·오류가 「이 운영체제에서는 조회하지 않는 항목」으로 「확인 불가」가 나옵니다.
- 관리자 권한이 필요한 방법은 쓰지 않았습니다. 일반 권한에서 읽지 못하는 항목은 「확인 불가」로 남습니다.
- CPU는 0.2초 동안의 짧은 표본이라 조회마다 크게 달라질 수 있습니다.
- 조회 기록은 이 브라우저(localStorage)에 숫자·상태·시각만 저장합니다(최근 200번). 다른 브라우저나 다른 PC에는 이어지지 않습니다. 앱이 꺼져 있을 때는 알림을 감지하지 못합니다. 바탕화면 알림·이메일·서버 전송은 없습니다.
- 어두운 화면은 만들 수 없었습니다. 제공 꾸밈 검증기가 글자색 대비를 맞추려고 어두운 배경을 밝게 바꿔 버립니다(직접 시험해 확인). 그래서 보라 강조색과 연한 보라 배경을 썼습니다.
- Windows 보안(Defender)·업데이트 날짜·열린 포트·시작프로그램 점검은 서버 쪽 코드가 필요해서 이 앱에는 넣지 못했습니다(제공 서버 코드를 고치지 않는 규칙).
- 22단계 이후 판정, 마무리 판정 기준(F1~F6)에 어떻게 보일지는 알지 못합니다. 통과를 미리 말하지 않습니다.
- 다른 사람이 이 안내만 보고 따라 해 본 적은 아직 없습니다.

## 8. 같은 결과를 다시 만드는 순서

1. 저장소를 받고 `git switch final-assault`.
2. 저장소 맨 위에서 `npm ci`, `node --test test/*.mjs` → 277건 통과를 확인합니다.
3. `on-client` 폴더에서 `npm run demo` → 브라우저에서 `http://127.0.0.1:5189/` → 보호 현황 → 「내 PC 기록·추이·위험 알림」에서 「다시 조회」를 눌러 위 시연 순서를 따라 합니다.

## 9. 제출 (포장 없이)

1. 작업을 커밋하고 GitHub에 올립니다(push). 강제로 덮어쓰지(`--force`) 않습니다.
2. `git rev-parse HEAD`로 40자리 커밋 번호를 확인합니다.
3. 포털 「과제」 화면의 「마무리 자료 제출」 창에서 결과 주소에 저장소 주소, 검증 메모에 40자리 커밋 번호를 적고 제출합니다.
